# jarvis-cli

Терминальный Jarvis: агенты, циклы и связка — там же, где вы работаете.

Настольная панель Jarvis умеет смотреть за агентами, крутить циклы и вести
связки. `jarvis-cli` делает то же самое из командной строки: без окон, по ssh,
внутри tmux — и без потери смысла. Состояние общее с панелью: один и тот же
`~/.jarvis`, те же циклы и связки. Что запустили в терминале — видно в панели, и
наоборот.

```
 Jarvis · local                                    1 ждёт ответа · 2 в работе
 
 ● jarvis   выполняет Bash                                              19:59
 ◆ lct      Снимать ли падающий тест или чинить?                        19:56
 ✓ desktop  Готово — подключайтесь по RDP ещё раз                       14:38

 ██░░░░░░░░ 5ч 17% · нед 15% · Fable 18% · до 20:59
 ↑↓ выбор · ↵ чат · s экран · x прервать · 1-9 ответ · l циклы · q выход
```

Шапка и выделенная строка идут на подложке, значок и проценты окрашены по
смыслу: бирюзовое — в работе, жёлтое — ждёт человека, красное — сломалось.
Внутри чата реплика человека лежит на подложке во всю ширину, ответ агента —
обычный текст с полем, вызов инструмента — узкая полоса: роль видна раньше,
чем прочитано первое слово.

## Живое окно

Просто `jarvis` — и вы внутри: список сессий обновляется сам, стрелки выбирают,
Enter открывает чат, набранное в чате уходит агенту.

| Клавиша | Что делает |
| --- | --- |
| `↑ ↓` или `k j` | выбрать сессию; в чате — прокрутка |
| `Enter` | открыть чат; в чате — отправить набранное |
| `s` | экран сессии как есть |
| `x` | прервать агента |
| `1`…`9` | ответить вариантом на вопрос с меню |
| `f` или `Ctrl-F` | отбор: набранное оставляет похожие строки, найденное подсвечивается |
| `/` | командная строка окна |
| `l` / `b` | циклы / связки |
| `?` | все клавиши, разделами |
| `Ctrl-L` | перерисовать экран |
| `Esc` | назад; в чате с набранным — стереть набранное |
| `q` | выход; `Ctrl-C` сперва стирает набранное, второй раз подряд — выходит |

Внизу — полоска лимитов. Выделение держится за сессией, а не за строкой:
список пересортировывается сам, и курсор не уезжает на чужой чат.

Одиночные команды (`jarvis ls`, `jarvis reply …`) никуда не делись — они
удобнее в скриптах и когда действие ровно одно.

В окне живут и связки: `b` — список, `n` — завести новую (форма спросит
каталог, имя, базовую ветку и гейты — по одному вопросу, Enter соглашается с
умолчанием), Enter — пульт. На пульте видно руки с их
состоянием, очередь слияний и последние события, а действия там же, где взгляд:
`m` — влить голову очереди, `n` — завести руку (спросит задачу), `p` — пауза,
Enter — открыть чат выбранной руки. Долгое (git, ssh, подъём агента) уходит в
фон: окно слушается клавиш всё это время и говорит, чем кончилось.

Внутри окна работает та же командная строка, что снаружи: `/` открывает её из
любого вида, дальше знакомые команды — `/chat lct`, `/limits`, `/loops`,
`/merge`, `/run ~/proj`. Tab дополняет, палитра под строкой показывает, что
подходит, и что каждая команда делает. Незнакомая команда — не ошибка: `/model
opus`, `/effort high`, `/compact` уходят самому агенту, потому что человек,
набравший их, хочет попасть именно к нему. Сообщение, которое начинается со
слэша, экранируется вторым: `//etc/hosts не трогай`.

Строка ввода — нормальное поле, а не «дописать в конец»: стрелки двигают
курсор, Home/End (Ctrl+A/Ctrl+E) — к краям строки, Alt+←/→ (Alt+B/Alt+F) ходят
по словам, Ctrl+W и Alt+D стирают слово, Ctrl+K и Ctrl+U — до конца и всю
строку, Ctrl+Y возвращает стёртое (Alt+Y листает кольцо), Ctrl+Z отменяет
правку. Ctrl+X открывает набранное в `$EDITOR` — длинный промт пишут там, где
видно и начало, и структуру. Стрелка вверх поднимает прошлые отправленные
сообщения, как в шелле.

Перевод строки внутри сообщения: Alt+Enter, Ctrl+O, Shift+Enter (где терминал
умеет) — или обратная косая в конце строки перед Enter, если не умеет ни одна
из них. В многострочном сообщении стрелки принадлежат курсору, а с верхней
строки вверх снова означает историю; лента листается PageUp/PageDown.

`@` подставляет путь к файлу: список того, что лежит рядом, показывается прямо
под строкой, Tab дополняет общим куском, а когда общего нет — ходит по кругу.
Пути считаются от каталога открытой сессии.

Если клавиша ведёт себя не так, `JARVIS_KEYLOG=~/keys.log jarvis` запишет, что
именно прислал терминал: терминалы шлют одну и ту же клавишу по-разному, и без
записи такое не проверить.

## Установка

Нужен Rust 1.87+ и `git`. Поддерживаются Linux и macOS.

```sh
git clone https://github.com/arklual/jarvis-cli
cd jarvis-cli
cargo build --release
install -m 755 target/release/jarvis-cli ~/.local/bin/jarvis
```

Или одной командой, если Rust уже стоит:

```sh
cargo install --git https://github.com/arklual/jarvis-cli --locked
```

Единственная внешняя зависимость времени выполнения — `ssh`, и то лишь для
удалённых машин. Ни Node, ни Python, ни системных библиотек.

## Что должно быть на той стороне

На машине, где живут агенты, работает `jarvis-node` — он слушает
`$JARVIS_DIR/node.sock` (по умолчанию `~/.jarvis/node.sock`) и знает всё о
сессиях: кто работает, кто спрашивает, где транскрипт. Это тот же узел, с
которым говорят панель и телефон, ставить отдельно ничего не нужно.

```sh
export JARVIS_DIR=~/.jarvis   # если каталог не по умолчанию
jarvis ls
```

Тильда раскрывается сама — даже если её оставил шелл (в fish `export
JARVIS_DIR=~/.jarvis` доносит её строкой).

Если агенты живут на сервере, а не здесь, локального узла на этой машине и не
будет: заведите её как удалённую и работайте через `-m` (ниже).

## Команды

| Команда | Что делает |
| --- | --- |
| `jarvis` | живое окно: список, чат, экран — в нём живут (см. ниже) |
| `jarvis ls` | список сессий разово |
| `jarvis reply <id> <текст>` | ответить агенту |
| `jarvis answer <id> <n>` | выбрать вариант n в вопросе с меню |
| `jarvis stop <id>` | прервать агента |
| `jarvis screen <id>` | экран сессии как есть |
| `jarvis chat <id> [-f]` | лента чата; `-f` — следить вживую |
| `jarvis cmd <id> /model opus` | слэш-команда пульта в сессию |
| `jarvis projects` | где на машине работали |
| `jarvis run <каталог>` | поднять агента в каталоге |
| `jarvis limits` | лимиты аккаунта по окнам |
| `jarvis machines` | машины и связь с ними |
| `jarvis machine add <имя> <user@host>` | добавить машину (пишется в общий `settings.json`) |
| `jarvis loop new` | завести цикл — диалогом, с каталогом заготовок |
| `jarvis loop …` | циклы: `ls`, `show`, `start`, `stop`, `say`, `presets`, `rm` |
| `jarvis bundle new` | завести связку |
| `jarvis bundle hand <id> <задача>` | добавить руку и поднять её агента |
| `jarvis bundle …` | связка: `ls`, `show`, `merge`, `pause`, `rm` |
| `jarvis notify` | печатать события по мере появления |

Сессию можно называть началом идентификатора или началом имени проекта —
достаточно, чтобы совпадение было одно: `jarvis chat jar`, `jarvis reply ef09
да, давай`. Точное имя сильнее чужого начала: при живых `api` и `api-gateway`
`jarvis chat api` откроет именно `api`.

Текст ответа, начинающийся с дефиса, отделяется двойным дефисом:
`jarvis reply abc -- --json это часть сообщения`.

## Удалённые машины

Список машин берётся из `settings.json` панели — заводить их дважды не нужно.
Если панели нет, машина заводится отсюда: `jarvis machine add vps me@vps`
(в тот же файл, не ломая чужих ключей). `jarvis machines` покажет, кто на связи.
Дальше `-m`:

```sh
jarvis -m vps ls
jarvis -m vps chat lct -f
```

`machine add` сразу проверяет связь и, если её нет, говорит чем именно: запрет
по ключу («разложи ключ: `ssh-copy-id …`»), неизвестный хост, незнакомый
отпечаток. Запись при этом остаётся — почините ключи, и она заработает без
повторного добавления.

Связки и циклы живут там же, где машина, на которой их завели: `jarvis -m vps
bundle new` и `jarvis -m vps` → `l`/`b` → `n` заводят их на сервере. Дальше всё
идёт туда: worktree рук и песочница цикла создаются на той машине, гейты и сам
агент запускаются там же, а каталог по умолчанию конструктор спрашивает у неё —
путь этого компьютера на чужой машине бессмыслен.

Под капотом поднимается `ssh -N -L` на сокет узла и гасится при выходе. Локаль
на ту сторону не уезжает (`SendEnv=-LC_*`), поэтому чужой сервер не встречает
вас предупреждениями `setlocale`.

## Циклы

Цикл — рутина, которую агент крутит сам: у него есть **конец** (гейты плюс
критик: сколько раз подряд всё должно сойтись) и **стены** (токены, итерации,
минуты). Стены проверяются перед итерацией, а не после — упереться в них на
середине хода нельзя.

Цикл живёт в окне целиком: `l` — список, `n` — новый (пять вопросов с
умолчаниями), Enter — журнал итераций, `s` — запустить, `x` — остановить. Ход
виден в строке состояния, окно всё это время слушается клавиш. Снаружи то же
самое командами:

```sh
jarvis loop new              # диалог: семь вопросов, у каждого умолчание
jarvis loop ls
jarvis loop show nightly     # журнал итераций: что сделал, чем кончилось
jarvis loop start nightly    # прогон прямо здесь, с печатью итераций
```

Команды из головы не вводят: источник задач и гейты выбираются из каталога
заготовок (`jarvis loop presets` покажет его целиком) — от «issue с меткой
agent» до «падающие тесты pytest». Выбранное вставляется обычной строкой и
правится тут же, в том же вопросе.

```
Откуда брать задачи ───────────────────────────────────────────────
  Просто
    без команды            работать по одной цели
  GitHub
    issue с меткой agent   классика ночного цикла: людям — обсуждение, агенту — метка
  ▸ все открытые issue     маленький репозиторий, где агенту можно всё
  Rust
    падающие тесты cargo   список красных тестов — по одному на итерацию
  ↑↓ выбор · ↵ взять · esc отмена · набирай — отбор
```

Выбирают стрелками, набранное отбирает строки той же нечёткой мерой, что и
палитра команд. В пайпе и в чужом терминале, где стрелки не доедут, остаётся
ввод номером.

Итерации идут в песочнице-worktree, ответ агента читается как JSON (кэш-токены
считаются в расход), критик отвечает `OK`/`RETURN`/`ASK` строго первой строкой.
`ASK` останавливает прогон и показывает вопрос — цикл не имеет права
додумывать за человека. Ответ уходит ему командой `jarvis loop say <цикл>
<текст>`: он попадёт в следующую итерацию как вмешательство человека, которое
важнее всего остального в промте.

## Связка

Связка — несколько агентов «в 10 рук» над одним проектом: у каждой руки свой
worktree, слияния идут очередью.

```sh
jarvis bundle new                 # каталог, база, гейты
jarvis bundle hand api "вынести очередь в свой модуль"
jarvis bundle ls
jarvis bundle show api       # руки, их состояние, очередь
jarvis bundle merge api h2   # влить голову очереди
jarvis bundle pause api      # всем рукам стоп
```

Убрать связку: `jarvis bundle rm <id>` (в окне — `d`, спросит подтверждение).
Пока в ней есть работающие руки, отказывает — их сначала останавливают
(`pause`) или настаивают флагом `--force`. Ветки рук не удаляются никогда: в
них лежит работа. Worktree сносятся только по `--clean`, и то лишь чистые —
git сам откажется убирать дерево с незакоммиченной правкой.

Рука получает свой worktree рядом с проектом (`../wt-<имя>`), ветку `team/<имя>`
и задачу с правилами: без коммитов очередь слияний руку не увидит.

Вливается только голова очереди с зелёными гейтами и свежим ребейзом, `ff-only`;
грязный чекаут — отказ с объяснением. При конфликте ребейз откатывается, а рука
получает сообщение и чинит сама.

## Уведомления

`jarvis notify` печатает переходы построчно — по одному событию, по мере
появления. Дальше это связывается с чем угодно:

```sh
# Linux
jarvis notify | while read -r line; do notify-send "Jarvis" "$line"; done

# macOS — голосом
jarvis notify | while read -r line; do say "$line"; done
```

Печатаются именно переходы: спросил, закончил, упёрся в лимит, сорвался. Начало
работы новостью не считается — иначе ленту выключают на второй день. Текст
«закончил» берётся из последней реплики самого агента, приехавшей вместе с
событием, так что вчерашняя сводка в сегодняшнем уведомлении не появится.

## Оформление

Палитра ролями, как в [pi](https://github.com/earendil-works/pi): цвет не
украшение, а смысл строки — зелёное «сделано», жёлтое «нужен человек», красное
«сломалось», приглушённое — подписи и время. Где есть truecolor, берётся он;
иначе цвета честно приближаются палитрой из 256. Цвет и Unicode определяются
сами: `NO_COLOR`, `TERM=dumb`, вывод в файл или пайп — и
остаётся чистый текст, значки становятся ASCII. Ширина берётся у терминала,
длинные строки режутся по видимой ширине, а не по байтам, поэтому кириллица и
эмодзи не рвут разметку.

На светлом терминале палитра меняется целиком: своя, а не «та же потемнее» —
на белом жёлтый становится невидимым, а серый грязным. Определяется по
`COLORFGBG`, а слово человека сильнее: `JARVIS_THEME=light` или `dark`.

Разметка в ответе агента становится начертанием, а не пропадает: **жирное** —
весом, *курсив* — курсивом, `код` — цветом, ссылка — подчёркиванием, блок кода
— полосой слева с названием языка, таблица — колонками. Заголовки по уровням,
вложенные списки с отступом. Подчёркивание внутри слова остаётся частью имени:
`snake_case_name` не рассыпается на курсив.

Кадр уходит в терминал построчно и только изменившимися строками, завёрнутый в
синхронный вывод: экран не мерцает и не тратит канал по ssh. Где терминал
понимает kitty keyboard protocol, различается Shift+Enter — просим молча, не
спрашивая (запрос стоил бы двух секунд на старте); выключается переменной
`JARVIS_NO_KITTY`.

`--json` даёт машинный вывод для скриптов.

## Разработка

```sh
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --all -- --check
```

CI гоняет то же самое на `ubuntu-latest` и `macos-14`.

Устройство: `core/` — протокол узла, реестр сессий, машины, состояние на диске;
`engine/` — движки циклов и связки; `ui/` — чистые функции отрисовки (строки
проверяются тестами, а не глазами); `app.rs` — команды; `cli.rs` — разбор
аргументов.
